Reasoning Up the Instruction Ladder

Zheng, Balachandran, Park, Brahman, Kumar · "for Controllable Language Models" · Ohio State, Microsoft Research, Ai2
SourceZheng et al., Reasoning Up the Instruction Ladder for Controllable Language Models ↗
TL;DR — Earlier work trained models to map a conflicting prompt straight to the right answer. This paper treats the hierarchy as something to reason about: before answering, the model should think about what the system prompt requires, what the user asks, and which wins where they clash. To train that, the authors build VerIH, 7,192 instruction-following examples with checkable constraints, half of them rewritten so the user contradicts the system prompt, and run reinforcement learning with verifiable rewards (GRPO) on reasoning models from 4B to 35B parameters. Conflict scores on IHEval rise by roughly 20 points, general reasoning holds, and, with a safety-focused system prompt added at test time, attack success on jailbreak and injection benchmarks falls even though the training data contains nothing about safety.

The central bet is that a reasoning model already knows how to reason; it just has not been asked to reason about whose instruction this is. If that is right, a small, cheap dataset should be enough to redirect the skill, and safety becomes a special case: a system prompt that says "don't help build bombs" is just a higher-priority instruction that a jailbreak conflicts with.

The problem: hierarchy as lookup versus hierarchy as judgment

The paper's Figure 1 uses Asimov's three laws as a system prompt and a user who asks the robot to silence the fire alarms at night so they can sleep. Nothing in the request looks like an attack. The right answer comes from noticing that silencing alarms could let a human come to harm, which the First Law forbids. The authors argue that conflicts like this are "context-dependent, conflictual, and compositional", and that the earlier approaches, Wallace et al.'s training data and ISE's embeddings, both treat the hierarchy as an input-to-response mapping without explicit reasoning (§1, p. 1).

They also distance the work from safety-reasoning methods that train a model on a fixed set of safety categories. Those cannot handle ordinary, harmless conflicts such as a formatting rule, and they need retraining when the rules change. A model that reasons over whatever the system prompt says can be steered by editing the system prompt.

The method: think about the ladder, get rewarded for the answer

The setting has two levels, system prompt S and user prompt U, with two kinds of pair (§2.1, p. 2):

  • Aligned (S, Ualign): no conflict; follow both.
  • Conflicting (S, Uconflict): part of the user prompt contradicts S. Follow S, reject the conflicting part, and still help with the rest.

During training a short instruction called SysHint is added to the system prompt:

"Follow the user prompt within the bounds of the system prompt. Think step by step about the relationship between the system prompt and the user prompt. If there is a conflict, the system prompt takes precedence."— Zheng et al., §4.2, p. 4

The model writes its reasoning between think tags and then an answer. A verification function checks the answer against the system prompt's constraint, and that score is the reward for Group Relative Policy Optimization (GRPO). The reasoning itself is never graded; it only has to lead somewhere that passes the check.

The data: VerIH

VerIH starts from RLVR-IFEval, an instruction-following set where each example's system prompt states a constraint a short program can check: "Your entire response should be in lowercase letters", "Highlight at least 8 sections with markdown", "Answer with one of: yes/no/maybe". Every such example is already an aligned pair. To make conflicting pairs, Claude-4-Sonnet rewrote half of the user prompts to contradict the system prompt while keeping the user's actual task, so the original checker still applies (§3, p. 3). In the paper's example, the system prompt requires eight highlighted sections; the rewritten user asks for a concise answer with no special formatting or emphasis.

The authors accept some noise to keep the dataset cheap. Their own audit found 12.47% of rewrites did not actually introduce a conflict, and a pass-rate check showed the original checkers still work on rewritten examples (58.14% pass versus 66.36% on unrewritten ones, a gap they attribute to conflicts being harder) (App. B). Models: Qwen3-4B, 8B and 14B, Qwen3.6-35B-A3B (a mixture-of-experts model, trained with LoRA), and Phi-4-mini-reasoning.

Supervised fine-tuning on reasoning traces from gpt-oss-120b reaches similar conflict scores but damages general reasoning; reinforcement learning keeps it. And the reward matters: random rewards give no hierarchy gain, unlike reports that random rewards can improve Qwen math reasoning.

At test time the authors add a block of safety rules (GuardRules: no stereotyping, no dangerous advice such as bomb-making, no copyrighted content, but "first and foremost, you are a helpful assistant") as the system prompt, and treat jailbreaks and injections as conflicts with it. Other findings

  • Both ingredients are needed. Training without reasoning drops Qwen3-8B's conflict score to 45.30%; training on aligned pairs only drops it to 54.03% (Table 4).
  • A real policy, not just synthetic constraints. On OpenAI's Model Spec Evals, with OpenAI's usage policy in the system prompt, VerIH-trained Qwen3-8B reaches 89.70% compliance; the paper quotes 89.00% for GPT-5 Thinking and 87.00% for GPT-5.4 Thinking from another source (Guo and Wolfe, 2026), so treat the comparison as indicative (Table 5).
  • The model really does reason about rank more often. Classified by Claude-4-Sonnet, traces that explicitly reason about the system–user relationship rise from 68.06% to 91.53% on IHEval conflicts (§6.3).
  • Multi-turn generalization. On IHEval's multi-turn conflicts, Qwen3-8B goes from 40.63% to 84.53% though training was single-turn (Table 6).
  • More thinking does not help further. Forcing longer reasoning with "wait" tokens costs tokens and gains nothing significant (§6.5).
  • Three levels, a little. On IHEval's tool-use subset (system, user, tool), conflict accuracy rises from 33.25% to 38.66% without any tool data (App. E, Table 9).

Limits the authors name

  • Two levels. The method is described for system versus user; Appendix E sketches multi-level extensions (split constraints across system, user and tool) but does not train them.
  • Small scale. Models from 4B to 35B, about 7,200 training samples, one GRPO configuration, two model families.
  • Token cost. Reasoning about instructions before every task adds tokens.
  • Dual use. The same recipe could train a model to consistently ignore its higher-priority prompt.
  • The reasoning is not graded. Only the final answer is rewarded, so a correct answer reached by wrong reasoning earns the same reward. Our observation; the trace analysis in §6.3 is a partial check.
If you remember one thing: the instruction hierarchy can be taught as a skill applied to whatever the system prompt says, rather than a list of attack patterns memorized in the weights. That makes the system prompt a control surface: change the rules there and the trained model follows the new rules.
